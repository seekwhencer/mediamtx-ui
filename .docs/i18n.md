## Projekt-Kontext

- Frontend: React 19, Vite 8, JavaScript (kein TypeScript), react-router-dom v7, @tanstack/react-query
- Einstieg: `frontend/src/main.jsx` → `App.jsx` → `Layout` → Seiten
- Sprache wechseln: `TopBar.jsx` (Sprach-Umschalter einbauen)
- Keine i18n-Pakete installiert. Nötig: `react-i18next`, `i18next`
- Optional: `i18next-http-backend` (JSON aus `/locales` laden), `i18next-browser-languagedetector` (Browser-Sprache erkennen)

## 1. Installation

```bash
cd frontend
npm install react-i18next i18next --save
# optional:
npm install i18next-http-backend i18next-browser-languagedetector --save
```

`i18next` = Kern (Übersetzungen, Plurals, Interpolation). `react-i18next` = React-Binding (Hook, Trans, Provider).

## 2. Setup: `frontend/src/i18n.js`

Neue Datei neben `main.jsx`. Zwei Varianten:

### Variante A: Ressourcen direkt im Bundle (einfach, kein Backend nötig)

```javascript
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';

import en from './locales/en.json';
import de from './locales/de.json';

const resources = {
  en: { translation: en },
  de: { translation: de },
};

i18n
  .use(LanguageDetector)
  .use(initReactI18next) // bindet i18n-Instanz an react-i18next (Context)
  .init({
    resources,
    fallbackLng: 'en',
    supportedLngs: ['en', 'de'],
    interpolation: {
      escapeValue: false, // React escaped bereits (XSS)
    },
    react: {
      useSuspense: true, // default; Suspense bei asynchronem Laden
    },
  });

export default i18n;
```

### Variante B: HTTP-Backend (JSON aus `public/locales`)

```javascript
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import Backend from 'i18next-http-backend';
import LanguageDetector from 'i18next-browser-languagedetector';

i18n
  .use(Backend) // lädt /locales/<lng>/<ns>.json
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    fallbackLng: 'en',
    debug: true,
    interpolation: { escapeValue: false },
  });

export default i18n;
```

Dateien: `frontend/public/locales/en/translation.json`, `frontend/public/locales/de/translation.json`.

### In `main.jsx` importieren (vor dem Render)

```javascript
import './i18n'; // muss gebundelt werden, Reihenfolge egal, aber vor App-Render
```

Wichtig: `i18n.use(initReactI18next)` macht die Instanz für alle Komponenten verfügbar (React Context).

## 3. Übersetzen in Komponenten

### useTranslation-Hook (Hauptweg, Function Components)

```jsx
import { useTranslation } from 'react-i18next';

function MyComponent() {
  const { t, i18n } = useTranslation(); // defaultNS = 'translation'
  return <h1>{t('Welcome to React')}</h1>;
}
```

- `t` = Übersetzungsfunktion, `i18n` = Instanz (z. B. `i18n.changeLanguage('de')`)
- Namespace laden: `useTranslation('common')` oder `useTranslation(['page1', 'common'])`
  - `t` ist an die **erste** Namespace gebunden (getFixedT intern)
  - Andere NS: `t('key', { ns: 'common' })`
- `i18n`-Instanz ist NICHT an Namespace gebunden
- Suspense: Hook suspendiert, bis Übersetzungen geladen (bei HTTP-Backend).
  - `<Suspense fallback="loading">` drumherum, ODER `useSuspense: false` + `ready`-Flag selbst prüfen:
    ```javascript
    const { t, i18n, ready } = useTranslation('ns1', { useSuspense: false });
    if (!ready) return <Loading />;
    ```
  - Ohne Suspense/ready: Übersetzungen rendern vor dem Laden → `saveMissing` feuert fälschlich
- `keyPrefix` (react-i18next >= 11.12): `useTranslation('translation', { keyPrefix: 'very.deeply.nested' })` → `t('key')`
  - NICHT kombinierbar mit `t('ns:key')` Notation
- `lng` (react-i18next >= 12.3.1): `useTranslation('translation', { lng: 'de' })` → t-Funktion fix auf Sprache
- `i18n`-Override: `useTranslation('ns1', { i18n })` (eigene Instanz statt Default)

### t außerhalb von Komponenten

```javascript
import i18n from './i18n';
i18n.t('my.key');
```

### withTranslation HOC (Legacy, Class Components)

```jsx
import { withTranslation } from 'react-i18next';

class Legacy extends Component {
  render() {
    const { t } = this.props;
    return <h1>{t('Welcome to React')}</h1>;
  }
}
export default withTranslation('common')(Legacy);
```

### Translation Render-Prop

```jsx
import { Translation } from 'react-i18next';

<Translation ns={['translation', 'common']}>
  {t => <p>{t('look.deep', { ns: 'common' })}</p>}
</Translation>
```

## 4. Trans-Komponente (JSX in einer Übersetzung)

Nur nötig, wenn **React/HTML-Knoten in einem zusammenhängenden Satz** vorkommen (`<strong>`, Links, Komponenten). Sonst reicht `t()`.

```jsx
import { Trans } from 'react-i18next';

function MyComponent({ person, messages }) {
  const { name } = person;
  const count = messages.length;

  return (
    <Trans i18nKey="userMessagesUnread" count={count}>
      Hello <strong title={t('nameTitle')}>{{name}}</strong>, you have {{count}} unread message. <Link to="/msgs">Go to messages</Link>.
    </Trans>
  );
}
```

JSON:
```json
"nameTitle": "This is your name",
"userMessagesUnread_one": "Hello <1>{{name}}</1>, you have {{count}} unread message. <5>Go to message</5>.",
"userMessagesUnread_other": "Hello <1>{{name}}</1>, you have {{count}} unread messages. <5>Go to messages</5>."
```

### Index-Regeln (wichtig!)

Kinder von `<Trans>` werden **indexiert** (Position im children-Array):
- String → bleibt String
- Objekt → Interpolation
- Element → wird zu `<x></x>`, x = Index im children-Array (Kind-Index startet bei 0 neu)

Beispiel-children: `['Hello ', <strong>, ', you have ', {count}, ' unread messages. ', <Link>, '.']` → `<strong>` = `<1>`, `<Link>` = `<5>`.

### Named-Components-Form (v11.6.0, lesbarer)

```jsx
<Trans
  i18nKey="myKey"
  defaults="hello <italic>beautiful</italic> <bold>{{what}}</bold>"
  values={{ what: 'world' }}
  components={{ italic: <i />, bold: <strong /> }}
/>
```

- JSON muss dann **Named-Tags** (`<italic>`) statt Index-Tags (`<0>`) enthalten
- Selbstschließende HTML-Tag-Namen sind reserviert (`link`, `img`, `media` …)
- Gleiche Komponente mehrfach nutzbar

### Props-Override aus der Übersetzung (v11.5.0)

```json
"myKey": "This is a <CustomLink href=\"https://example.com/\">link</CustomLink>."
```
→ überschreibt `href` der Komponente pro Sprache.

### Einfache HTML-Elemente (v10.4.0)

`<br/>`, `<strong>bold</strong>`, `<p>text</p>` bleiben im JSON lesbar (nur ohne Attribute, nur Text-Kinder).
Konfig: `transSupportBasicHtmlNodes` (default true), `transKeepBasicHtmlNodesFor` (default `['br','strong','i','p']`).

### Interpolation & Plural in Trans

```jsx
<Trans>Hello {{ name }}</Trans>            // JSON: "Hello {{name}}"
<Trans>Hello {{ firstname: person.name }}</Trans> // JSON: "Hello {{firstname}}"

<Trans i18nKey="newMessages" count={messages.length}>
  You have {{ count: messages.length }} messages.
</Trans>
// JSON: "newMessages": "You have one message."
//       "newMessages_plural": "You have {{count}} messages."
```

- `count`-Prop: seit v16.4.0 optional, wenn `{{ count }}` in children (muss JS-`number` sein)
- Listen: `<ul i18nIsDynamicList>{items.map(...)}</ul>`

### Trans-Props (alle optional)

| Prop | Beschreibung |
| --- | --- |
| `i18nKey` | Key (optional bei Natural-Language-Keys); `ns:key` möglich, besser `ns`-Prop |
| `ns` | Namespace |
| `t` | eigene t-Funktion |
| `count` | Plural-Zahl |
| `context` | Context-Feature |
| `tOptions` | Extra-Optionen für t() |
| `parent` | Wrapper-Komponente (React < 16 Pflicht) |
| `i18n` | eigene Instanz |
| `defaults` | defaultValue statt children |
| `values` | Interpolation-Werte |
| `components` | Array[nodes] nach Index |
| `shouldUnescape` | HTML-Entities unescape |
| `transDefaultProps` | Default-Props |

### i18next react-Optionen (init)

```javascript
react: {
  bindI18n: 'languageChanged', // Events, die Re-Render triggern (default)
  bindI18nStore: '',
  transEmptyNodeValue: '',
  transSupportBasicHtmlNodes: true,
  transKeepBasicHtmlNodesFor: ['br', 'strong', 'i', 'p'],
  transWrapTextNodes: '', // z. B. 'span' (Google-Translate-Workaround)
  useSuspense: true,
  keyPrefix: undefined,
}
```

### Richtige Übersetzungs-Strings erzeugen

1. React DevTools → Trans-Instanz → `props.children`-Array inspizieren
2. `debug: true` in init → Console zeigt missing keys
3. `saveMissing: true` → Keys an Backend schicken
4. Index-Regeln verstehen (siehe oben)

## 5. Namespaces / mehrere Übersetzungsdateien

- Namespace = eine JSON-Datei. `ns: ['translation', 'common']`, `defaultNS: 'translation'`
- Lookup: `i18n.t('look.deep')` (defaultNS) oder `i18n.t('look.deep', { ns: 'common' })`
- `useTranslation(['translation', 'common'])` lädt beide, suspendiert bis geladen
- Lazy Loading: nur geladene Namespaces → nicht alles vorladen
- `fallbackNS`: NS-Fallback wenn Key nicht gefunden
- `nsSeparator` default `':'`

## 6. Wichtige i18next init-Optionen

| Option | Default | Beschreibung |
| --- | --- | --- |
| `resources` | undefined | Übersetzungen direkt (Variante A) |
| `lng` | undefined | Start-Sprache (überschreibt Detection); `'cimode'` = Keys ausgeben |
| `fallbackLng` | 'dev' | Fallback-Sprache; `false` = kein Fallback laden |
| `supportedLngs` | false | erlaubte Sprachen, z. B. `['en','de']` |
| `load` | 'all' | `'all'` → `['en-US','en','dev']`; `'currentOnly'`; `'languageOnly'` |
| `preload` | false | Sprachen vorladen (SSR) |
| `ns` | 'translation' | Namespaces zu laden |
| `defaultNS` | 'translation' | Default-Namespace |
| `fallbackNS` | false | NS-Fallback |
| `keySeparator` | '.' | Key-Trenner; `false` bei flachem JSON |
| `nsSeparator` | ':' | NS-Trenner |
| `pluralSeparator` | '_' | Plural-Trenner |
| `contextSeparator` | '_' | Context-Trenner |
| `ignoreJSONStructure` | true | flache Key-Lookup als Fallback |
| `saveMissing` | false | fehlende Keys an Backend (nur mit create-fähigem Backend) |
| `saveMissingTo` | 'fallback' | `'current'` / `'all'` |
| `missingKeyHandler` | false | Custom-Handler (braucht `saveMissing: true`) |
| `returnObjects` | false | Objekt als Ergebnis |
| `joinArrays` | false | Arrays joinen, z. B. `", "` |
| `interpolation` | {...} | `escapeValue: false` für React |
| `initAsync` | true | `false` nur bei sync-Backends (fs-backend) |
| `detection` | undefined | LanguageDetector-Optionen |
| `backend` | undefined | Backend-Optionen |

### LanguageDetector-Optionen (Beispiel)

```javascript
detection: {
  order: ['localStorage', 'navigator'],
  caches: ['localStorage'],
}
```

## 7. Sprache wechseln (UI)

```jsx
const { i18n } = useTranslation();
i18n.changeLanguage('de'); // verspricht, löst Re-Render (bindI18n: 'languageChanged')
i18n.language; // aktuelle Sprache
```

Sprach-Umschalter in `TopBar.jsx` einbauen: Buttons/Select → `i18n.changeLanguage(lng)`.

## 9. Einbau-Plan für mediamtx-ui

1. `cd frontend && npm install react-i18next i18next`
2. `frontend/src/locales/en.json` + `de.json` anlegen (Keys aus UI-Texten sammeln)
3. `frontend/src/i18n.js` (Variante A: Ressourcen im Bundle — passt zu Vite, kein extra HTTP-Backend nötig)
4. `main.jsx`: `import './i18n';` vor dem Render
5. Komponenten: `useTranslation()` → `t('key')` statt harter Strings
6. `TopBar.jsx`: Sprach-Umschalter (`i18n.changeLanguage`)
7. Trans nur für Sätze mit eingebetteten Elementen (Links, `<strong>`)
8. Optional: `i18next-browser-languagedetector` für Browser-Sprache + localStorage-Cache

## 10. Fallstricke

- `escapeValue: false` immer setzen (React escaped selbst)
- Suspense: bei asynchronem Laden `<Suspense>`-Boundary oder `useSuspense: false` + `ready`
- Trans-Index-Tags sind fragil → Named-Components-Form bevorzugen
- `keyPrefix` nicht mit `ns:key`-Notation kombinieren
- `lng` in init überschreibt LanguageDetector → bei Detector `lng` weglassen
- React Native/Hermes: `Intl.PluralRules`-Polyfill nötig (i18next >= 24) — hier nicht relevant (Browser)
- TypeScript: `react-i18next >= 13`, `i18next >= 23.0.1`, CustomTypeOptions — hier JS, nicht relevant
